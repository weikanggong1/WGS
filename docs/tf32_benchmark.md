# TF32 开发与真实测量状态

本版（F）已在真实单连续表型 chr21 完成全部 795 项串行任务，覆盖 Single、全部 coding/noncoding mask 和 ncRNA。19 份原生文件结构与原严格零模型比较通过；478,082 个 P 全部有效、可比较，原生 log 与 raw P 的一致性检查通过。以原 R 或本版任一 `P<0.05` 的联合范围验收，24,713 个 P 没有超过 `0.001`，最大 `-log10(P)` 绝对差为 `0.0003579714`。全部 P 的误差与非 P 关联数值差仍保存作诊断，不将这些诊断改写为全值相等。

进程墙钟为 **429.097 秒（约 7.15 分钟）**，每条染色体 300 秒的速度目标尚未达到。生产关联由 Python/PyTorch 完成，不调用 R；原 R 使用 FP64，R 只用于独立输出对照。匿名汇总见 [本版完整记录](../benchmarks/staar_chr21_native_tf32_2026-10-06.json)。

公开发布代码的独立完整复验为 **419.926 秒**：795 项任务、19 份原生文件、严格零模型和显著联合范围全部再次通过，最大 logP 差仍为 `0.0003579714`。CPU 回归为 642 通过、2 跳过。该次复验仅保留公开 stage profiler 和串行任务进度，移除了私有细分 profiler；两轮时间差不作为受控加速证据。下表保留初轮 F 的细分测量。

## 已取消的分量重建评估

旧候选使用多次 TF32 分量乘法重建高精度结果。用户因速度要求停止了评估，该版本不发布。停止时观察到 stage14 完成 325/795 项，耗时约 6082.2 秒：coding 221、noncoding 104，ncRNA 和 Single 尚未完成。完整精度、所有文件结构和端到端性能均未验收。

旧短流程从 388.52 秒到 242.79 秒的观测覆盖 10 项任务，其中 ncRNA 为空；它不能证明完整染色体 <=300 秒，也不能用作新原生 TF32 性能。旧已完成部分的误差与冻结版本另列在[历史匿名记录](../benchmarks/staar_tf32_optimization_2026-10-05.json)。

## 新候选的计算方式

生产路径使用一次 TF32 MMA 和 FP32 矩阵输出；小向量使用 FP32 GEMV/dot。保留原 Score、协方差、Burden、SKAT、ACAT-V、CCT 和 Saddle 公式，局部 mask 共用 u/V，所有权重合并计算。完整特征值保留，禁止用近似谱或替代检验缩短流程。移除为追求原 FP64 数值而做的分量重建、CPU 谱精度匹配和标量权重精度匹配。

已发布 0.2.0 的完整 FP64 对照保持其冻结记录，见 [benchmark](benchmark.md)及[原完整记录](../benchmarks/staar_chr21_serial_2026-10-05.json)。新运行只发布匿名汇总，不公开实际表型、样本、gene/位点结果或私有地址。

## 原生候选的定位实验

同公式纯 FP32 矩阵对照仍有超限。私有定位记录显示，当前两组近均值 SKAT 均走原 Saddle 分支，没有发生 moment 分支切换；共同放大 Q 和特征值会被原公式的最大特征值归一化抵消。最大超限项的原 R P 约为 0.43，不是小概率下溢。仅收紧求根和使用 log1p 未使全部 P 达标，因此这些诊断控制未作为生产默认。已用原 R 缓存 Q/谱及原编译函数复核该项：按原谱阈值和求根宽度得到的 P 与实际原版返回逐位一致；见下方缩放与容差控制。没有启动新的完整染色体慢评估，没有推送 main。

## 直接 FP32 数据准备

一块真实 GDS 输入包含 42,652 个样本、128 个变异及 468,418 个缺失调用。直接构建 FP32 slab 与旧 FP64 准备后 cast 的矩阵逐位一致；6 组完整/逆序子集、mean/minor 和 count/reference 对照的 MAF、MAC、缺失计数及方向均一致。完整样本的 mean/count 准备中位数从 0.06089 秒降到 0.04440 秒，少建 41.65 MiB 的临时 FP64 slab。见[匿名阶段记录](../benchmarks/staar_fp32_host_preparation_2026-10-05.json)。

该计时只覆盖同一已解码块的 CPU 准备与旧路径 cast，四次交替测量中首次作为预热；不包含 GDS 读取、H2D、关联或结果写出。它不是整条染色体加速比例。直接 FP32 准备冻结版的完整 CPU 回归为 444 通过、44 跳过、33 子测试通过；随后 tile 接入的 CPU 专项为 64 通过。GPU 数值和完整端到端目标仍未验收。

## 原公式的数值范围与求根控制

一项实际原版 SKAT 输入，经原单位谱阈值和原编译函数重算，P 与实际原版返回逐位一致。共同将 Q/谱乘 2^-16、1、2^16 后，归一化输入、根和 P 均逐位不变。原求根宽度 1e-8 给出 P=0.42826874；仅将宽度收紧至 1e-12，同一公式得到 P=0.39577203，与原版的 logP 差 0.0342713，两个控制都未进入 moment 分支。见[匿名原版控制记录](../benchmarks/staar_probability_scaling_2026-10-05.json)。

该证据表明此输入对原版根终止位置敏感，不能通过共同放大或单独收紧求根满足原版输出误差门槛。生产仍保留原阈值与宽度；这些控制不是新版已通过精度的结果。

## 大协方差矩阵的 tile 比较

同一真实操作数 `1216×42652 @ 42652×1216` 的原生 TF32 单乘，固定 BK=32、RNA 舍入和 FP32 累加。32×64、64×64、64×128、128×128 tile 的预热后主机墙钟中位数分别为 4.773、4.328、3.950、4.380 ms，64×128 最快。四者输出逐位一致，实际 TF32 MMA/RNA 检查通过，峰值分配显存约 401.64 MiB，见[匿名 tile 记录](../benchmarks/staar_native_tf32_tiles_2026-10-05.json)。

每候选包含一次冷启动、两次预热和三次测量；该记录不包含完整 Score/投影、谱和尾概率、GDS、零模型拟合或写出。只按预热后速度选 tile；逐位比较用于检查公式实现，不以 P 值接近程度选择参数。接入后对 426 与 1216 个变异的两组真实固定零模型输入进行了串行 GPU 核验，完整 u/V 均与原 tile 路径逐位一致；这没有解决此前的原 R P 误差。

## resident 路线的真实原生文件核验

三组原始 gene family（coding、noncoding、非空 ncRNA）及一个独立原 R 已运行的 Single 精确区间，共 377 个 P。每组均保留该 family 的全部原 mask 槽位、空结果和原生顺序；三组 gene 的 host/resident logP 差均为 0。与实际原 R 输出的最大 logP 差分别为 0.000158745、0.000110754、0.0000427981；Single 的 27 个 P 最大差为 0.000000481592。四个原生文件的类型、属性、顺序、标识和 NULL 结构全部通过，见[匿名核验记录](../benchmarks/staar_resident_paths_2026-10-05.json)。

这些核验加载相同冻结零模型；gene reference 从原 R 已存完整结果中按原目录独立提取，Single 使用同一精确区间独立 R 结果。该范围未覆盖所有 gene、所有 Single 区间或新拟合零模型，不能替代前述 248 P 探针仍有 5 个超限的结果。该 resident 接入时的 CPU 回归为 509 通过、45 跳过、33 子测试通过；后续可选 packed 入口的完整回归为 669 通过、45 跳过、33 子测试通过，运行时参数调整另通过 116 项专项检查。

实验串行使用一张 GPU；两张设备均有其他任务，速度比较不合格。本次 Single 实际解码 12,000 个位点，初始 MAC 合格 27 个；SDK 返回约 1.024 GB，读取 host 观察时间 9.247 秒，单 job 观察时间 10.885 秒。这些时间只定位读取成本，不能外推整条染色体时间。三个 family 和 Single 的峰值 GPU 分配均在 20 GiB 内，最大约 1.61 GiB。

另外比较两个真实单层位点的 singleton SDK 读取，各 3 次预热及 3 次交替测量。selected 返回字节约少 8.11 倍，但中位读取为 1.413/1.849 ms，flat 为 0.496/0.946 ms；因此保持原 singleton 选择规则。未外推多层位点或全染色体。

## 小矩阵并集实际触发

对当前只有截距的真实模型补充了小矩阵 route 成本检查。一个 47 列并集由一次 Score/协方差供两个 mask 复用；实际调用从 2 次降至 1 次，178 个 P 与此前 native 路线最大 logP 差 0.000000702241，与原 R 最大差 0.000158636，原生结构通过。GPU 峰值约 166.51 MiB，无 FP64 dense 产品。见[匿名记录](../benchmarks/staar_small_union_2026-10-05.json)。此数据的变化按矩阵形状选取；共享 GPU 下只确认减少计算次数，不报告速度改善比例。

## 2026-10-06 分阶段复核

可选 packed 入口的 174 次实际读取仅编译一个解包内核，解包主机记录从约 10.19 秒降至 0.70 秒；四类分析的 4 个文件、377 个 P 对原 R 的最大 logP 差为 0.000158636。使用相同输入的私有融合整数 decoder 与 64 KiB 缓冲候选也通过了全字段 native 控制对照和原 R 对照，但五个任务的总墙钟记录约 58 秒和 62 秒，没有显示明显端到端改善，因此尚未接入生产。读取仍约 13 秒，索引准备约 35 秒；阶段指标重叠，不能直接相加。见[本轮匿名记录](../benchmarks/staar_tf32_followup_2026-10-06.json)和[packed 输入说明](gds_packed.md)。

另一候选将一个 3,370 变异、26 权重检验的完整特征值外层调用从 25 次合为 1 次，完整谱逐位一致，86 个 P 的原 R 对照通过；记录约 3.04/2.96 秒，峰值由约 354 MiB 升至 2.38 GiB。大矩阵在当前 PyTorch/cuSOLVER 分支内部仍逐矩阵求谱，这不构成谱并行加速证据，候选保留在 private。整数 decoder 的 0–16 层与样本尾块另通过合成功能检查；这些检查不计入真实数据 benchmark。
