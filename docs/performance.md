# STAAR pipeline 的速度与计时

一个连续表型的 chr21 完整串行流程已通过原 R 文件对照：795 项任务、全部 15 个基因 mask、18 个关联文件、R/串行共八份 Single 元数据及一项零模型比较。GPU 串行进程区间为 **11,218.930 秒**，原 R 两个 CPU worker 的并行 wall 为 **24,170.535 秒**，本次观测比为 **2.154**。完整聚合值见 [串行验收与计时报告](../benchmarks/staar_chr21_serial_2026-10-05.json)。

早期真实区域任务中，部分 PyTorch pipeline 比原 R 函数慢。已分离计时的真实 100 kb 单变异区段，关联调用为 **21.794 秒**，其中原生 SDK 读取调用 **16.718 秒，占 76.7%**，读取是该区段的主要成本。代码还显示 CPU 数据准备、小矩阵调用和设备同步会增加耗时；完整染色体尚未分离这些环节的占比。下文保留历史计时，并给出当前完整串行结果。按用户要求，本轮完整 GPU 验收仅使用串行模式。

## 读取实测与代码中的成本

| 环节 | 实测或代码证据 | 对运行时间的影响 |
|---|---|---|
| GDS 读取 | 100 kb 区段：177 次 selected 读取，返回 3.860 GB SDK 缓冲区；读取调用 16.718 秒 | 磁盘等待、CoreArray 解压和 SDK 选择都发生在 GPU 统计之前。该计时没有继续分离这些内部环节。 |
| 样本与基因型准备 | 基因集合在 CPU 构造稀疏 dosage、按表型取样本、处理缺失并拼接矩阵，再送入 CUDA。单变异在 CUDA 解码和 MAC 预筛后，仍用 `dosage.cpu().numpy()` 将保留 dosage 回传 CPU，构造 `SparseMinorBlock`，经 `trait_dense` 填补和列筛选形成 F 连续密集副本，再送入 CUDA 的 `individual_score_variance` | 单变异存在 D2H→CPU 稀疏/密集准备→H2D 往返，增加同步、数组构造和复制成本；这一路径的独立耗时尚未分离。 |
| 小矩阵与同步 | 一些真实基因只有几个稀有变异，但每个注释权重都需加权谱、尾概率和最终标量；合法性判断、收敛判断及结果转换会读取 CUDA 标量 | 提交 kernel 和等待设备的固定成本可能超过小矩阵计算本身；这是代码支持的解释，尚无完整 profiler 分项比例。 |
| 原版舍入顺序 | FP64 有序稀疏求和、固定 FMA 累加次序和逐行二次型求和保留原 R 舍入 | 这些路径减少了任意重排归约的空间，不能直接用最快的矩阵乘法或低精度替换。 |
| 原生输出 | 正式 `.Rdata`/`.rds` 的结构组装、序列化和压缩在 CPU 完成，CLI 单独记录写出时间 | 原软件兼容文件写出属于端到端成本，GPU 统计时间不包含这部分。 |

原版参考使用 float64。三个真实集合的 FP32/TF32 score/协方差探针未达到严格 P 值容差，因此生产统计保留 FP64；详见 [精度实测](precision.md)。CUDA 整数解码、候选索引、单变异只求方差对角线和减少重复读取，是当前已实现的优化，见 [GDS 读取](gds.md)与[统计内核](statistics.md)。

上述 100 kb 区段包含 42,652 个分析样本、45,247 个 PASS 位点，保留 1,023 个 MAC 合格位点，执行 45 次 CUDA 解码。正式输出的 10,230 个 double 单元格全部通过原 R 的严格容差对照。SDK 字节数是返回缓冲区大小；实际存储读取量和解压量没有测量。原 R 对该最终区段没有对应函数计时，因此这里仅报告 GPU 路径内部的读取比例。[完整区段结果](gds.md#5-真实数据对照)

## 历史区域任务的速度

下表摘自 0.1.0 的同输入真实连续表型区域对照，保留该版本的原计时边界。函数时间含数据提取和检验，排除随后保存文件。集合使用匿名代号。

| 真实区域任务 | 原 R 函数，秒 | 0.1.0 GPU pipeline 函数，秒 |
|---|---:|---:|
| 非编码集合 A，全部类别 | 138.010 | 264.666 |
| ncRNA 集合 A | 20.696 | 141.297 |
| 单变异区段 A | 6.511 | 13.578 |
| 编码集合 B，missense | 15.479 | 14.674 |

该轮 GPU 入口报告 wall 为 817.508 秒，包括拟合、读取、mask、统计和输出。R 的 11 个函数加零模型阶段合计为 323.429 秒；原 R 未测量同等完整 CLI，因此这两个数不能直接形成端到端加速比。早期全量注释版本的非编码/ncRNA 时间为 478.106/348.508 秒，改用分块及按需注释读取后为 264.666/141.297 秒，说明重复注释扫描在这些区域任务中确有成本。[该版本完整结果及环境](benchmark.md)

历史七个真实集合的统计微基准曾测得串行中位 1.118 秒、批量 0.611 秒。该测量使用早期批量源码，仅含统计调用，排除 GDS、mask、拟合和输出；其源码匹配只核对 `batch_statistics.py`，未验证完整精度依赖。不同轮次的串行基准也变化，不能把跨轮差异全部归因于单项优化。[批量统计记录](statistics.md#可选批量统计与单变异方差)

## mask 批量与染色体并行的范围

软件保留可选 `statistics_execution="batched"`：把同一批中变异数相同的 mask 加权协方差一起提交谱求解，并行计算各行的 Saddle 搜索。一批来自同一次 gene 或 ncRNA 调用；其他滑窗入口可合并同一次调用内的多个窗口。不同 gene、入口调用和染色体之间不合并批次。pipeline 先逐集合完成读取与 score/协方差准备，再按工作空间预算提交统计批次。burden、ACAT-V 和最后的 CCT 继续使用已有路径。集合大小、空 mask、缓存命中和敏感谱校正都会改变批量规模；调用报告中的 `batch_diagnostics` 记录执行情况。本页完整基准只报告串行结果。

当前 batch 入口先转换权重来准备加权谱，生成最终结果时又转换一次三类权重；最终结果复用已算好的 SKAT P 值，不再重复这项谱检验。相比串行入口，这会增加权重转换与复制次数。`annotation_weight_execution` 可核对实际次数和累计耗时；本轮没有完整批量性能结论。

从代码看，批量模式可减少小谱和尾概率的提交成本；读取与基因型准备仍需完成。单变异已按块计算 score 和方差对角线，不经过 gene mask 的加权谱批量入口。[参数与内存预算](statistics.md#可选批量统计与单变异方差)

当前 CLI 按配置顺序执行染色体。染色体层并发需要独立进程或多 GPU 调度，每条染色体都重新核对模型样本与 GDS 行号。多个进程共用一个 GPU 和存储时，会同时增加显存、CPU 和读取压力；能否更快要以相同配置的实测判断。启动顺序、GPU 数量、CPU 线程和文件缓存状态都应进入运行记录。

下一步优化应先针对占时最高的阶段：减少重叠 mask 的重复读取；在相同样本、位点和求和顺序下复用准备结果；扩大可合并的小谱批次；用 profiler 区分 SDK、主机准备、传输和 kernel。任何改变 genotype、MAF、归约顺序或谱求解的优化，都需要重新对照正式原 R 文件。

## 保持原版输出的精度校正成本

新权重变换使用少量 CPU 标量 float64 `libm`，保持原 `exp`、`pow`、`sqrt` 与 ACAT-V 除法次序。CUDA 先筛选根接近零的敏感谱，仅选中的谱由锁定 CPU LAPACK 重算，工作区固定为原版 `66×矩阵阶数`，随后回到 CUDA 计算尾概率。[计算边界与安装](precision.md#保持原-saddle-舍入的精度边界)

18 个缓存真实 mask 的三类权重共 91,926 个元素与原 R 逐位一致。同一共享 A100 的五次预热转换探针如下；测量从 CUDA 的小型 MAF/PHRED 数组开始，仅覆盖权重转换。

| 转换步骤 | 18 个 mask 的平均时间 |
|---|---:|
| 输入回主机，包含等待与检查 | 1.665 ms |
| CPU 标量权重变换 | 14.707 ms |
| 三类权重传回设备 | 2.040 ms |
| 合计 | **18.411 ms** |

该套件有 1,421 个 MAF 和 13,900 个 PHRED 值，使用 36 次 D2H、54 次 H2D，逻辑 float64 载荷分别为 122,568 和 735,408 字节。同期旧 GPU 权重函数为 13.293 ms，权重精度修正增加约 5.118 ms。此计时不包含 GDS、关联检验、原始互补 PHRED 构造或敏感谱 CPU 求解，也没有配对 R 计时；全染色体校正成本由完整运行报告中的实际次数与累计耗时给出。

完整串行运行的实际精度校正成本如下。这些时间已包含在关联入口内。

| 精度校正边界 | 完整串行累计，秒 |
|---|---:|
| 权重转换，含检查、同步和复制 | 3.512 |
| 上项中的 CPU 标量变换 | 2.724 |
| 原始互补 PHRED 构造 | 0.429 |
| 参考谱传输及求解，含同步和初始化 | 14.480 |
| 上项中的 CPU 谱求解 | 13.780 |

权重调用 1,662 次、处理 200,045 个变异权重行，逻辑 D2H/H2D 载荷为 20,804,680/124,828,080 字节；651 个敏感谱使用参考 CPU 求解，CUDA 计算 43,212 个加权谱矩阵。权重转换与参考谱传输/求解分别占 `run_configuration` wall 的 **0.0313%** 与 **0.1291%**。这是有明确同步/复制边界的累计时间，CPU 标量和求解时间分别是其中子集；它们不提供完整 genotype 往返或纯 kernel 的占比。

## 完整串行运行的对照

本轮原 R 的 chr21 全部 18 个批次已完成：2 个 CPU worker、每个 BLAS 线程为 1，并行入口 wall 为 **24,170.535 秒，即 6 小时 42 分 50.535 秒**。它从冻结零模型开始，包含 R 批次启动、载入、函数、正式文件与逐 gene 验证文件写出；原始表型准备和零模型拟合另行验证。原 R 的函数时间合计为 46,101.251 秒，多个 worker 的耗时发生重叠，函数合计不等于用户等待时间。[原版调度与计时口径](base_reference_inventory.md#原版调度与计时口径)

| 类别 | 任务数 | 原 R 函数合计，秒 | GPU 串行入口合计，秒 | R/串行入口观测比 |
|---|---:|---:|---:|---:|
| Coding | 221 | 4,422.615 | 1,255.079 | 3.524 |
| Noncoding | 221 | 24,473.730 | 3,659.510 | 6.688 |
| ncRNA | 349 | 5,392.658 | 541.936 | 9.951 |
| Individual | 4 | 11,812.248 | 5,680.396 | 2.079 |

R 函数与 GPU job 都包含相应入口的数据准备和统计。GPU 的一次性候选索引另列，原 R 每 gene 函数重复扫描注释，因此按类入口比与整个流程比有不同边界。ncRNA 合计包括空 mask 快速返回，任务数表示入口数。

冻结执行源码 SHA-256 为 `c6362c6d392dce8c29668a9563a88182714571ebc8aa68285e5988a7ad423300`，实际 33 个执行及依赖文件匹配。18 个关联文件的 3,343,119 个 double 单元格全部满足 `abs=1e-10 + rel=1e-7 × |reference|`，结构差异和超容差单元格均为零，最大绝对差 `1.0914e-10`、相对差 `1.7740e-9`。四个 Single 文件的 R/串行八份元数据相等；正式零模型的 341,221 个 double 单元格最大绝对/相对差均为零。历史失败与局部诊断见 [全量原版记录](base_reference_inventory.md)。

本轮单变异扫描解码 13,733,596 个位点，保留 318,132 个 MAC 合格位点；真实 AF tie 为一个，半缺失和全部 allele 缺失均为零，最大 Bit2 层数为二。历史 100 kb pilot 的零 tie 记录仍属于其局部范围。

| 完整流程时间边界 | 秒 | R/串行观测比 |
|---|---:|---:|
| 原 R 两个 worker 的并行 wall | 24,170.535 | — |
| GPU 串行 shell 进程区间 | 11,218.930 | 2.154 |
| GPU 串行 `run_configuration` wall | 11,215.356 | 2.155 |

串行进程区间从 shell 驱动启动前，到串行 CLI 成功退出后的完成标记，包含 Python 启动、配置展开、最终报告保存和少量 shell/标记开销。原始输入准备和外层正式文件校验另计。用户取消了随后模式，驱动的取消退出不改变此前成功完成的串行区间；其余模式不进入本轮验收及速度表。

`run_configuration` 中关联入口合计为 11,136.920 秒，其他独立阶段如下。

| 独立阶段 | 串行秒 |
|---|---:|
| CUDA 初始化 | 0.038 |
| 新零模型拟合 | 3.494 |
| GDS 读取器与样本映射 | 2.858 |
| 一次性候选索引 | 35.590 |
| 正式零模型及缓存写出 | 12.721 |
| 正式关联文件写出 | 23.188 |
| 未细分入口开销 | 0.546 |

共享 A100 上，本进程峰值 Torch allocated/reserved 为 2,615.225/8,580 MiB。启动快照可见两个 GPU compute 进程，PID 无法映射到当前容器，也观察到其他 pipeline；没有资源隔离或逐进程占用归因。文件缓存未清。上述比值描述这一次 chr21 配置的观测结果。

GPU `--report` JSON 的计时字段可这样解读：

| 字段 | 实际边界 |
|---|---|
| `total_seconds` | `run_configuration` 从 CUDA 初始化、模型拟合或载入，到索引、关联和正式输出的 wall；排除 Python 启动、最后的报告元数据收集与 JSON 保存、外层验证器 |
| `cuda_initialization_seconds` | 上述 total 内的 CUDA 初始化 |
| `null_fit_seconds` | 模型拟合或缓存载入，取决于输入配置 |
| `gds_setup_seconds`、`index_preparation_seconds` | 读取器/样本映射和一次性候选索引准备 |
| `jobs[].seconds` | 各关联入口的读取、主机准备、传输和统计，包含返回后的 CUDA 同步；排除一次性索引及正式文件写出，是入口 wall 而非纯 GPU kernel 时间 |
| `native_association_output_seconds` | 正式关联文件组装、序列化和压缩 |
| `native_null_and_cache_output_seconds` | 正式零模型与模型缓存写出 |
| `genotype_reader.native_reads` | SDK flat/selected 调用次数及返回字节；当前没有读取时间字段，多染色体配置只保留最后一条染色体的读取器计数 |
| `annotation_weight_execution` | 实际权重调用、行数/注释量、逻辑传输字节、CPU 标量变换及包含同步/复制的转换 wall |
| `precision_eigen_execution` | 实际 CPU 敏感谱次数、CPU 求解时间、含传输/初始化的总时间，及 CUDA 谱/尾概率次数 |

权重和谱计时嵌套于 job 时间中，不应再次加到端到端总时间。未细分开销包含候选索引计时之前的区间表载入等工作。原 R 并行入口从冻结零模型开始，另写逐 gene 验证文件；GPU 入口新拟合零模型。原 R 在用户空间容器中运行，Python 原生运行；这些边界差异已保留在公开报告中。

下面的 Python 示例读取已公开的聚合结果，不读取个体数据：

```python
import json
from pathlib import Path

# 在仓库根目录运行；此文件只含汇总与校验元数据。
benchmark_report = json.loads(
    Path("benchmarks/staar_chr21_serial_2026-10-05.json").read_text()
)
assert benchmark_report["accepted_scope"] == "serial_only"
assert benchmark_report["accepted"] is True
serial_report = benchmark_report["gpu"]["serial"]
print({
    "serial_shell_interval_seconds": benchmark_report["process_end_to_end"][
        "intervals"]["serial_shell_interval_seconds"],
    "run_configuration_wall_seconds": serial_report["run_configuration_seconds"],
    "function_seconds_by_kind": serial_report["by_kind"],
    "annotation_weight_execution": serial_report["annotation_weight_execution"],
    "precision_eigen_execution": serial_report["precision_eigen_execution"],
})
```

这份报告能区分入口、索引、文件写出和新增精度校正的成本。它还不能把每个 job 继续拆成完整的 GDS 解压、主机准备、H2D、score/协方差、谱和 Saddle 时间；这种归因需要另加 profiler 或独立阶段计时。正式文件一致性检查与性能计时应分别保存。[完整流程](pipeline.md)、[完整染色体参数](chromosome.md)、[原版文件校验](r_native_output.md)
